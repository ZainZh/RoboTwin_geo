# GeometryFlow 当前路线：一步一步解释

## 一句话版本

基础学习策略负责“把鞋拿过去”，几何接口负责“鞋还差多少才能到正确功能位姿、
末端应该怎样补偿、现在能不能松手”。我们没有用几何替代学习，而是把学习策略
不容易稳定学会、但能够用 SE(3) 明确计算和验证的部分交给几何模块。

当前正式 closed-loop 测试从 expert-admitted grasp 后的 placement phase 开始，
所以数字衡量的是“已经拿住鞋以后能否可靠放置和释放”，不是完整抓取到放置成功率。

## 训练阶段学了什么

当前封存 v2 包含两个学习部分：

1. **名义操作策略**：从演示学习抓取后的搬运、靠近和放置轨迹。它接收物体 A、
   目标 B 的点云、机器人状态以及相对几何状态，生成一段双臂动作。
2. **候选关系 verifier**：训练物体上学习哪一个示范中的 object-in-gripper
   关系最适合当前观测，并在几何候选存在对称歧义时选择或否决候选。

此外，训练演示构成一个功能关系库，保存“示范物体怎样被夹爪拿住”以及“物体
相对目标应该达到什么姿态”。它不是按测试 shoe ID 查询答案；测试时根据当前
点云在训练关系中选择候选。

当前正式 v2 的关系库后端以 raw point geometry、PCA/Chamfer 候选和一个学习式
candidate verifier 为主，**并不是 NDF 已经成为获胜编码器**。NDF/UTONIA 在这条
主线中的下一职责是改善点对应、在线 SE(3) 校正和不确定性，而不是解释当前
96/100 的全部增益。

## 一次测试 episode 实际发生什么

### 1. 观察

系统接收：

- 被操作鞋子的相机点云 \(\mathcal P_A\)；
- 目标斜台/几何 marker 的相机点云 \(\mathcal P_B\)；
- 左右末端位姿和夹爪状态。

目标点云首先建立目标功能坐标系。鞋子点云与当前夹爪位姿一起生成若干
object-in-gripper 候选，包括可能的对称方向。

### 2. 选择“鞋在夹爪中是怎样拿住的”

候选 verifier 和点云拟合代价共同选择一个训练示范关系。当前封存阈值要求
抓取拟合代价不高于 \(3\times10^{-4}\,\mathrm{m}^2\)，或者 verifier 对普通
几何选择执行有置信依据的 veto。若关系不可信，系统退回 PCA 路径；PCA 路径
不能触发正式几何释放。

这一步解决的是：相同的末端位姿对不同抓取位置意味着不同的鞋子位姿；如果不
知道 object-in-gripper 关系，就不能从“鞋应该怎样动”正确换算成“夹爪应该
怎样动”。

### 3. 计算鞋子到目标还差多少

由当前鞋子位姿 \((R_A,p_A)\) 和目标功能位姿
\((R_A^*,p_A^*)\) 得到世界坐标下的中心位移与相对旋转

\[
R_{err}=R_A^*R_A^T, \qquad t_{err}=p_A^*-p_A.
\]

对鞋子上的任一点 \(x_i\)，对应的刚体 action flow 为

\[
f_i=t_{err}+(R_{err}-I)(x_i-p_A).
\]

它同时表达平移和旋转，不会像全局池化 token 那样丢失“物体不同位置应怎样
运动”的结构。

### 4. 学习动作与解析几何动作如何分工

名义学习策略在每次调用时都会执行一次，保证 candidate 和 baseline 的网络
路径一致。随后根据当前几何误差路由：

- 大于 **1.5 cm 或 5°**：使用解析的抓取约束刚体修正；
- 小于上述恢复阈值：继续使用学习策略生成的名义动作。

若鞋子到末端的杠杆向量为 \(l\)，物体变换 \((R,t)\) 对应的末端平移为

\[
\Delta p_{eef}=t+(R-I)l,
\]

末端旋转为 \(\log R\)。系统把它均分到动作 horizon 中。这是当前所谓
**analytic rigid action flow**：几何决定恢复方向，学习策略保留其擅长的名义
行为。

### 5. 为什么几何模块还要拥有松爪权

只修正笛卡尔动作而让原策略随时松爪是不闭合的：策略可能在几何条件刚接近但
尚不稳定时把鞋放掉。因此当前 v2 使用双边终态门控：

- 释放前，几何接口否决名义策略的提前开爪，保持主动夹爪闭合；
- 平移误差不超过 **2 cm**、旋转误差不超过 **5°**；
- 误差经过 \(\alpha=0.5\) 的 EMA 平滑；
- 连续 **10 次**策略调用满足条件才 latch；
- latch 后固定笛卡尔动作并打开主动夹爪。

“双边”意味着几何接口既负责 transition 的前半边（没有满足条件就不许松），
也负责后半边（满足后主动松）。正式失败分析表明，这一步是当前增益最强的可见
机制：很多 baseline 已到达目标或发生接触，但仍然闭爪、徘徊或超时。

## 这到底是 planning 还是 learning

它是**带结构化几何接口的学习策略**，不是纯 planning：

- 抓取、搬运、避开异常姿态和名义动作分布来自学习；
- 关系 verifier 也是从训练物体上学习；
- 解析模块只处理刚体运动和终态判断这类结构已知的问题；
- 没有搜索整条机器人轨迹，也没有用几何控制器替代完整策略。

可以把它理解为：学习策略提出技能行为，几何接口在关键阶段提供一个带物理语义
的 residual、验证器和状态机。

## 它和“把 PA3FF/NDF/HeRO token 拼给 diffusion policy”有什么不同

特征条件方法通常是：

```text
逐点或全局特征 -> policy latent -> action
```

模型必须自己学会特征中哪些维度代表对应、怎样变成 SE(3)、何时可信，以及何时
松爪。我们的接口是：

```text
逐点特征/原始几何
    -> 带置信度的 object-in-gripper 与 object-to-target SE(3)
    -> 可验证的刚体 flow
    -> 连续动作修正 + 离散阶段转换
```

因此 NDF、UTONIA、PA3FF 或 HeRO 特征并不是竞争架构，它们可以替换第一行的
对应与置信度后端。我们的研究问题是：**如何让几何表征以具有因果约束的形式
进入技能执行，而不是仅作为网络可能使用、也可能忽略的条件。**

## 当前已经证明和没有证明的边界

已经证明：在两个 held-out shoe folds 的 100 个严格配对 placement-phase
episode 中，带双边
终态转换的封存 v2 达到 96/100，相同 relation/verifier/analytic recovery 但关闭
终态转换的 ablation 为 82/100，绝对提升 14 个百分点；两折方向一致。这个对照
隔离证明的是终态转换，不能把 14 个百分点全部归因于完整 GeometryFlow。完整
camera/analytic route 相对 nominal policy 目前只有 6/10 对 0/10 的小规模扩展门，
还需要正在准备的 paper-scale nominal-only 消融。

还没有证明：抓取后每一时刻都由实时视觉重新估计鞋子位姿。当前选择关系以后，
主要用末端 proprioception 传播鞋子位姿，假设鞋子没有在夹爪中滑动。这个假设
解释了目前少数 candidate 失败，也决定了下一步：用新鲜相机点云和逐点表征在线
校正 object-in-gripper SE(3)，并让置信度进入恢复和释放门控。
